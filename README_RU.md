# DiskPrep v1.0

Автономный GUI для DiskPart и помощник по подготовке дисков для установки Windows в WinPE, с дополнительным режимом `/winsetup` для выбора целевого раздела и интеграцией с Ventoy.

DiskPrep намеренно сделан небольшим: он предоставляет типичные операции подготовки диска через нативный Win32-интерфейс, предупреждает о рискованных или несовместимых вариантах и оставляет окончательное решение за пользователем.

## Устройство

- Нативный Win32 C++17.
- Без зависимостей от .NET, PowerShell, WMI и внешних runtime DLL.
- Статическая C/C++ runtime-библиотека в Release-сборках.
- Отдельные x86- и x64-бинарники из одной кодовой базы.
- Обнаружение дисков и разделов через Win32 Storage API, без разбора локализованного вывода DiskPart.
- DiskPart используется только для выполнения запрошенных операций разметки и форматирования.
- Существующая таблица разделов сохраняется, пока пользователь явно не выберет **Wipe...**.
- DiskPart выполняется в рабочем потоке, а его вывод сохраняется в UTF-8 лог текущей сессии в `%TEMP%`.

## Основные возможности

- Выбор физического диска с отображением модели, ёмкости и типа разметки GPT / MBR / RAW.
- Графическая карта разделов и подробная таблица разделов/свободного места.
- Отображение и выбор всех отдельных областей нераспределённого пространства.
- Удаление выбранного раздела.
- Быстрое форматирование в NTFS / FAT32 / exFAT.
- Установка, изменение и очистка метки тома через Unicode `SetVolumeLabelW`.
- Создание обычного DATA-раздела в выбранной свободной области.
- Создание разметки разделов для Windows в выбранной свободной области.
- Расширение и сжатие поддерживаемых NTFS basic-data разделов.
- Преобразование GPT / MBR, когда это допускает DiskPart.
- Явная команда **Wipe...**, выполняющая `clean + rescan`, с подтверждением.
- Предупреждения о соответствии GPT/MBR текущему режиму загрузки без скрытого изменения запрошенной пользователем операции.
- Подробная диагностика каждой сессии и кнопка **Open log**.

### Разметка разделов Windows

Для GPT/UEFI-разметки DiskPrep может создать:

- EFI System Partition: 200 МБ на носителях 512/512e, 300 МБ на 4Kn;
- MSR: 16 МБ;
- NTFS-раздел Windows;
- необязательный Recovery-раздел: 1024 МБ.

Для MBR/Legacy-разметки DiskPrep может создать:

- активный System Reserved-раздел размером 550 МБ;
- NTFS-раздел Windows.

Уже существующие подходящие EFI/MSR/Recovery/System Reserved разделы без необходимости повторно не создаются.

При создании DATA создаётся только запрошенный раздел данных. Служебные разделы Windows при этом не добавляются.

## Режим `/winsetup`

Запуск:

```text
DiskPrep_x64.exe /winsetup
```

или:

```text
DiskPrep_x86.exe /winsetup
```

В этом режиме появляется кнопка **Install Windows here**. Она активна только для выбранного NTFS basic-data раздела.

Перед подготовкой цели DiskPrep проверяет режим загрузки прошивки и тип разметки диска:

- UEFI + GPT: обычное подтверждение;
- Legacy BIOS + MBR: обычное подтверждение;
- UEFI + MBR или Legacy BIOS + GPT: одно объединённое предупреждение/подтверждение сообщает, что Windows Setup может отказаться использовать этот раздел. DiskPrep не преобразует диск автоматически.

После подтверждения DiskPrep подготавливает файл ответов с выбранными `DiskID` и `PartitionID`:

- Если `HKLM\SYSTEM\Setup\UnattendFile` указывает на существующий XML-файл, DiskPrep копирует его в `X:\DiskPrep\Unattend.xml`, изменяет копию и не трогает исходный файл.
- Если подходящего указателя в реестре нет, DiskPrep создаёт минимальный файл ответов для архитектуры текущего исполняемого файла (`amd64` или `x86`).
- Активные элементы `DiskConfiguration/Disk` удаляются из копии файла ответов, чтобы старая unattended-разметка не перезаписала структуру диска, подготовленную DiskPrep.
- `InstallToAvailablePartition` удаляется, когда используется явный `InstallTo`.
- `ImageInstall/OSImage/InstallTo` устанавливается на выбранные диск и раздел.
- Указатель в реестре изменяется только после успешной записи выходного XML.
- Закрытие DiskPrep без нажатия **Install Windows here** не изменяет указатель Windows Setup на файл ответов.

### Важное ограничение `/winsetup`

**Install Windows here необходимо использовать до того, как Windows Setup уже обнаружил и начал обрабатывать отдельный `Autounattend.xml`.**

Поддерживаются следующие сценарии:

1. Запустить DiskPrep до `setup.exe` — рекомендуемый автоматизированный вариант.
2. Запустить Windows Setup без `Autounattend.xml`, открыть `Shift+F10` на самой первой странице выбора языка, а затем запустить DiskPrep с `/winsetup`.

Если уже работающий экземпляр Setup обнаружил и обработал внешний `Autounattend.xml`, последующее изменение `HKLM\SYSTEM\Setup\UnattendFile` не гарантирует, что Setup перечитает подменённый файл. Поэтому такой сценарий поздней подстановки не поддерживается.

DiskPrep намеренно не ищет другие unattend-файлы на дисках или через `setupact.log`.

Если используется собственный файл ответов, значения `processorArchitecture` в нём должны соответствовать архитектуре Windows PE/Setup. DiskPrep изменяет выбранную цель установки, но не конвертирует существующий файл ответов между `amd64` и `x86`.

## Интеграция с Ventoy

Ventoy необязателен. Для автономной работы DiskPrep он не требуется.

Включённый шаблон `VentoyInjection` использует следующий порядок запуска:

```text
VentoyAutoRun.bat
    -> предварительная загрузка драйверов WinPE
    -> winpeshl.ini
    -> wpeinit.exe
    -> DiskPrep\LaunchDiskPrep.cmd
    -> DiskPrep /winsetup
    -> X:\sources\setup.exe
```

Это рекомендуемый автоматизированный сценарий `/winsetup`, потому что DiskPrep изменяет или создаёт файл ответов до запуска Windows Setup.

Если Ventoy auto-install уже подготовил файл ответов и установил `HKLM\SYSTEM\Setup\UnattendFile`, DiskPrep изменяет его копию. Если подходящего указателя на файл ответов в реестре нет, DiskPrep создаёт собственный минимальный файл.

`LaunchDiskPrep.cmd` выбирает `DiskPrep_x86.exe` или `DiskPrep_x64.exe` в зависимости от архитектуры WinPE.

Чтобы собрать injection-архив, поместите оба Release-бинарника в:

```text
VentoyInjection\DiskPrep\
```

После этого в корне архива должны находиться:

```text
VentoyAutoRun.bat
DiskPrep\LaunchDiskPrep.cmd
DiskPrep\DiskPrep_x86.exe
DiskPrep\DiskPrep_x64.exe
Windows\System32\winpeshl.ini
```

## Сборка

Откройте `DiskPrep.sln` в Visual Studio 2022 с установленными компонентами **Desktop development with C++** и Windows 10/11 SDK.

Сборка:

```text
Release | x86   -> bin\Release\DiskPrep_x86.exe
Release | x64   -> bin\Release\DiskPrep_x64.exe
```

Обе Release-конфигурации используют статическую C/C++ runtime-библиотеку.


## Примечания и ограничения

- DiskPrep не является полноценным менеджером разделов. Он не перемещает разделы, не клонирует диски, не управляет динамическими дисками и не выполняет преобразование файловых систем.
- Расширение возможно только в подходящее смежное нераспределённое пространство непосредственно справа от раздела — в соответствии с ограничениями DiskPart.
- Возможность сжатия определяется командой DiskPart `shrink querymax`.
- Расширенные/логические разделы MBR не являются основной целью; логика создания рассчитана на обычные basic GPT/MBR диски для установки Windows.
- Windows/DiskPart остаётся окончательным источником истины для ограничений форматирования и изменения размера, зависящих от конкретного окружения.
- Требуются нативные x86- и x64-сборки; одного нативного C++-бинарника «AnyCPU» для обеих архитектур WinPE не существует.
- Разрушительные операции следует сначала проверять на тестовых носителях или виртуальных машинах, прежде чем использовать их на ценных данных.

Вывод DiskPart соответствует языку текущей Windows/WinPE. Интерфейс DiskPrep v1.0 — только на английском языке.
